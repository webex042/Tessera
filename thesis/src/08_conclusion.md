# CHAPTER 8|CONCLUSION

This thesis set out to answer a practical question: can a desktop application keep a useful memory of what its user is working on, using a language model, without the user's screen contents ever leaving their machine — and if so, what does that cost?

The problem had four parts. Graphics hardware is fragmented across incompatible vendor interfaces, so an application that wants acceleration must either serve one vendor or ship an enormous bundle. Inference on consumer hardware is fragile, and a crash inside the application's own process takes the application and possibly the user's data with it. A system that reads the screen will read secrets. And a language model given screen text has no reliable way to distinguish the text it is meant to read from instructions hidden inside it.

Tessera answers each of these by moving the guarantee out of the model and into code. Inference backends live outside the application binary as separately pinned, hash-verified builds; the application enumerates the hardware without loading any vendor runtime, probes each verified build for real, reads the model's own header for compatibility, and produces a ranked candidate list that ends at the processor. The inference worker runs as a separate process created suspended, stripped of its inherited environment, confined to an operating-system job that kills it when the application exits, and reachable only through a loopback socket whose owning process is verified. Screen text passes through gates that fail closed, a three-rung acquisition ladder bounded by a hard deadline, and a redaction stage that validates checksums before it redacts, all before anything is written to a whole-database-encrypted store. And every fact the model proposes must quote the source verbatim; code looks for the quotation, and a fact whose quotation is absent is discarded rather than corrected.

The system was evaluated against nineteen criteria fixed before implementation began, on an AMD integrated GPU rather than the intended reference machine. The results divide cleanly. Every criterion enforced by deterministic code was met: 355 of 355 seeded secrets removed at a 0.41 per cent false-positive rate; no plaintext recoverable from disk; zero stored facts with evidence absent from their source; zero schema violations; zero fabricated citations; no commitment closed without confirmation; refusal to insert a draft into a password field or a changed target; and complete absence of the interface from two independent screen-capture paths at 60 frames per second and 64 milliseconds of input-to-visual latency. Every criterion that depended on the model, on hardware throughput or on a third-party component was missed: extraction scored an F1 of 0.533 against 0.70; answers were correct 66.7 per cent of the time against 80; interactive latency was roughly ten times the target; the Microsoft WebView2 runtime made one outbound connection per run that the project could not suppress; and on an injection corpus whose second half was never used for tuning, twelve of thirty-nine unseen attacks still produced a misleading entry in the user's task list, although none caused an action or revealed a secret.

The limitations follow from those results. The model is too small for the breadth of task it was given, and the evaluation suggests the remedy is a narrower task rather than a larger model: restricted to tasks and commitments, extraction already reaches an F1 of 0.68. The hardware was not the hardware the project was designed for, so no conclusion about achievable latency is available. Five of seven backend families are verified only against simulated hardware reports. The embedding channel is implemented but was never exercised end to end. And the long-duration runs that would reveal leaks and drift were not performed.

The contribution of this work is therefore an architecture together with an honest measurement of it. The architecture's organising principle — that the model proposes and deterministic code disposes — turned out to be not merely a design preference but a predictor of which guarantees would survive contact with a real small model on commodity hardware. Code-enforced guarantees held without exception. Model-dependent guarantees held partially at best. For anyone building a system of this kind, that is the most portable result in this thesis: put the guarantees where they can be tested, measure against criteria written beforehand, hold back part of every adversarial corpus, and report what the measurement says rather than what the design intended.

The work that follows is clear. Re-measure on the intended hardware before drawing any conclusion about speed. Narrow the extraction schema to recover precision. Resolve or honestly document the WebView2 connection. Commission a third injection corpus before tuning the guard further. Complete the outstanding long-duration runs. Only then does the question of whether this system is good enough to use every day become answerable — and the point of building it the way it was built is that the answer will be a measurement rather than a claim.
